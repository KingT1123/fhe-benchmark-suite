\noindent\textit{Note:} energy is read from \texttt{/sys/class/powercap/intel-rapl:0/energy\_uj} (the \texttt{package-0} domain), in microjoules. This path is served by the \texttt{intel\_rapl\_msr} and \texttt{intel\_rapl\_common} kernel drivers -- confirmed via \texttt{lsmod} and the kernel boot log -- not the separate \texttt{amd\_energy} hwmon driver; AMD's RAPL-compatible model-specific registers are read through the same driver Intel systems use, which is also why the sysfs path keeps the \texttt{intel-rapl} name on this AMD CPU. The underlying hardware resolution is $2^{-16}$\,J $\approx 15.26\,\mu$J per step (from the kernel boot log), and the counter updates continuously rather than on a fixed polling interval, confirmed by rapid back-to-back reads showing a fresh value almost every time. The counter wraps at \texttt{max\_energy\_range\_uj} $=$ 65{,}532{,}610{,}987\,$\mu$J ($\approx$65.5\,kJ, roughly 14--24 minutes of continuous runtime depending on load); the run scripts and the benchmark program account for this, adding the range back whenever a reading is lower than the previous one. Inside Docker the \texttt{powercap} directory is hidden, so the energy/memory runs mount the host's \texttt{intel-rapl:0} directory read-only into the container.

A commit cannot contain its own hash, so the tag points to the next commit, which only writes this hash into the report; it differs from the commit above in \texttt{report/} alone (\texttt{git diff \textit{<commit>} seal-final-v3 -{}- experiments/} prints nothing). The full parameter grid (Table~\ref{tab:paramgrid}) is at \texttt{experiments/config/param\_grid.csv}. The benchmark's input values use a fixed seed, but SEAL generates its keys and encryption randomness afresh in every run, as it must. Repeated runs therefore reproduce timings and sizes up to ordinary system noise (captured by the confidence intervals reported throughout), while noise-budget values can differ by a few bits from run to run (Section~\ref{sec:results}, BGV at $N{=}4096$/category~1).

\subsection{Reproduction steps}

The steps below re-measure everything. The run scripts skip any cell whose raw file already exists (so an interrupted sweep can resume), so the committed results must first be moved aside; they then remain available for comparison. Commands marked \texttt{sudo} need root for the CPU-governor setting and the RAPL counter. Measured values will differ from the committed ones within ordinary run-to-run variation.

\begin{lstlisting}
git clone https://github.com/KingT1123/fhe-benchmark-suite.git
cd fhe-benchmark-suite
git checkout seal-final-v3
cd experiments

# 0. Keep the committed results aside, start from empty directories
mv results/raw results/raw_committed
mv results/final results/final_committed
mkdir -p results/raw results/final

# 1. Build the pinned image and compile the harness
docker build -t seal-env seal
(cd seal && bash docker_build_and_run.sh)
cd scripts

# 2. Timing scenarios (exact grids used in this report)
sudo bash -c 'GRID=../config/param_grid_le8192.csv bash run_standard_docker.sh'
sudo bash -c 'GRID=../config/param_grid_n16384cat1.csv bash run_standard_docker.sh'
sudo bash -c 'GRID=../config/param_grid_le8192.csv bash run_constrained_docker.sh'
sudo bash -c 'GRID=../config/param_grid_le8192.csv bash run_edge_batch_docker.sh'

# 3. Storage, noise budget, CKKS error, configuration records
GRID=../config/param_grid_le8192.csv bash run_extended_metrics_docker.sh
GRID=../config/param_grid_n16384cat1.csv METRICS=size \
    bash run_extended_metrics_docker.sh
GRID=../config/param_grid_n16384.csv METRICS=config_metadata \
    bash run_extended_metrics_docker.sh

# 4. Composite and packing (N=8192/category 1)
sudo bash run_composite_docker.sh
sudo bash run_packing_docker.sh
bash run_composite_controls_docker.sh
bash run_composite_checks_docker.sh

# 5. Dedicated energy/memory runs. make_energy_plan.py sizes the
#    timed blocks from the new Standard latencies; skip it to reuse
#    the committed config/energy_plan.csv of this campaign.
python3 aggregate.py --scenario=standard
python3 make_energy_plan.py
sudo bash run_energy_memory_docker.sh standard
sudo bash run_energy_memory_docker.sh constrained

# 6. Aggregate everything, regenerate the report's tables
for s in standard constrained edge_batch size noise_trace \
         ckks_error config_metadata composite composite_controls \
         composite_checks packing; do
    python3 aggregate.py --scenario=$s
done
python3 make_report_tables.py
\end{lstlisting}

After a \texttt{sudo} run, \texttt{sudo chown -R \$USER ../results/} returns the files to the user. A full re-run takes roughly a day on the laptop of Table~\ref{tab:env}, most of it in the Standard timing sweep.
