\noindent\textit{Note:} energy is read from \texttt{/sys/class/powercap/intel-rapl:0/energy\_uj} (the \texttt{package-0} domain), in microjoules. This path is served by the \texttt{intel\_rapl\_msr} and \texttt{intel\_rapl\_common} kernel drivers -- confirmed via \texttt{lsmod} and the kernel boot log -- not the separate \texttt{amd\_energy} hwmon driver; AMD's RAPL-compatible model-specific registers are read through the same driver Intel systems use, which is also why the sysfs path keeps the \texttt{intel-rapl} name on this AMD CPU. The underlying hardware resolution is $2^{-16}$\,J $\approx 15.26\,\mu$J per step (from the kernel boot log), and the counter updates continuously rather than on a fixed polling interval, confirmed by rapid back-to-back reads showing a fresh value almost every time. The counter wraps at \texttt{max\_energy\_range\_uj} $=$ 65{,}532{,}610{,}987\,$\mu$J ($\approx$65.5\,kJ, roughly 14--24 minutes of continuous runtime depending on load); the run scripts and the benchmark program account for this, adding the range back whenever a reading is lower than the previous one. Inside Docker the \texttt{powercap} directory is hidden, so the energy/memory runs mount the host's \texttt{intel-rapl:0} directory read-only into the container.

\subsection{Code and data}

Source code, build scripts, and configuration are version-controlled at:
\begin{center}
\url{https://github.com/KingT1123/fhe-benchmark-suite}
\end{center}
{\sloppy Result data \emph{is} version-controlled in the same repository: per-configuration raw output under \nolinkurl{experiments/results/raw/}, the aggregated CSVs used for every table and figure under \nolinkurl{experiments/results/final/}, and the randomized run-order seed of each sweep in \nolinkurl{experiments/results/run_metadata.csv}. Incomplete $N{=}16384$ fragments excluded from the analysis are kept, not deleted, in the separate directory \nolinkurl{experiments/results/} \nolinkurl{raw_quarantine_N16384_incomplete/}. Per-run console logs are not tracked.\par}

All SEAL code and results in this report correspond to the commit
\begin{center}
\sealcommit
\end{center}
tagged \texttt{seal-final-v1} in the repository (\texttt{git checkout seal-final-v1}). The only later commit records this hash in the report source itself.

The full parameter grid (Table~\ref{tab:paramgrid}) is at \texttt{experiments/config/param\_grid.csv}. The benchmark's input values use a fixed seed, but SEAL generates its keys and encryption randomness afresh in every run, as it must. Repeated runs therefore reproduce timings and sizes up to ordinary system noise (captured by the confidence intervals reported throughout), while noise-budget values can differ by a few bits from run to run (Section~\ref{sec:results}, BGV at $N{=}4096$/category~1).

\subsection{Reproduction steps}

\begin{lstlisting}
git clone https://github.com/KingT1123/fhe-benchmark-suite.git
cd fhe-benchmark-suite/experiments/seal

# 1. Build the SEAL Docker image and compile the harness
bash docker_build_and_run.sh

# 2. Run each scenario (from experiments/scripts/)
cd ../scripts
bash run_standard_docker.sh
bash run_constrained_docker.sh
bash run_edge_batch_docker.sh
# storage, noise budget, CKKS error:
bash run_extended_metrics_docker.sh
# dedicated energy/memory runs (see Methodology), need sudo:
python3 make_energy_plan.py
sudo bash run_energy_memory_docker.sh standard
sudo bash run_energy_memory_docker.sh constrained
# composite and packing (single-row grids, N=8192/category 1):
bash run_composite_docker.sh
bash run_packing_docker.sh

# 3. Aggregate raw output into final results
python3 aggregate.py --scenario=standard
python3 aggregate.py --scenario=constrained
python3 aggregate.py --scenario=edge_batch
python3 aggregate.py --scenario=size
python3 aggregate.py --scenario=noise_trace
python3 aggregate.py --scenario=ckks_error
python3 aggregate.py --scenario=config_metadata
python3 aggregate.py --scenario=composite
python3 aggregate.py --scenario=packing
\end{lstlisting}

Energy measurement requires \texttt{sudo} for RAPL access; the run scripts prompt for this where needed.
